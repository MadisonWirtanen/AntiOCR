# AntiOCR

AntiOCR 是一个纯前端的图片文字抗识别工具。它提供两类处理方式：

- **微信 GIF 模式**：将普通图片转换为可正常发送和打开的 GIF，适合微信场景。
- **静态图片模式**：导出带文字结构扰动的 PNG / JPG，适用于需要静态文件的场景。

所有图片处理都在浏览器本地完成，图片本身不会上传到服务器。

## 功能

### 微信 GIF 模式

GIF 模式是本项目推荐用于微信发送的方案。

当前测试中，微信对 GIF 与普通静态图片的文字识别行为存在差异，因此将图片转换为 GIF 在部分场景下可以降低自动 OCR 的触发或识别效果。

提供两种生成方式：

- **兼容模式**：优先保持原图观感与微信中的正常显示。
- **四相模式**：使用多帧动态结构，作为兼容模式之外的补充方案。

> 平台的 OCR 策略可能随客户端版本、图片内容和服务端策略变化，本项目不能保证在所有环境中都阻止文字识别。

### 静态图片模式

当目标平台需要 PNG / JPG 等静态图片时，可以使用静态模式。

内置三档预设：

- **阅读优先**：优先保留文字可读性。
- **平衡**：兼顾可读性与抗识别效果，默认选项。
- **拦截优先**：使用更明显的结构扰动。

静态模式使用的主要处理包括：

- 行级扰动
- 微断笔
- 伪轮廓
- 纹理干扰
- 前景文字区域检测

高级参数可以进一步调整处理强度。

## 使用方法

1. 打开 `index.html`。
2. 选择或拖入一张 PNG、JPEG 或 WebP 图片。
3. 根据用途选择 **微信 GIF 模式** 或 **静态图片模式**。
4. 根据需要调整模式、尺寸与强度参数。
5. 处理完成后下载生成的文件。

在微信场景下，建议直接发送下载得到的原始 GIF，不要截图、复制预览内容或重新转换成静态图片。

## 隐私

图片的读取、处理和导出均在浏览器本地完成。

GIF 模式会从公共 CDN 加载 `gif.js` 编码组件，但图片数据不会因此上传到 CDN。静态图片处理无需上传图片。

## 兼容性

建议使用较新的 Chromium、Edge、Chrome、Firefox 或 Safari 浏览器。

GIF 生成需要浏览器能够访问 `jsDelivr` 或 `unpkg` 以加载 GIF 编码组件。

## 限制

AntiOCR 的目标是降低 OCR 自动识别的稳定性，而不是提供绝对的文字隐藏或加密能力。

不同 OCR 引擎、平台版本、图片压缩方式以及二次转码都可能影响最终效果。对于敏感信息，请不要仅依赖图片抗 OCR 处理来实现保密。
